# 本地到线上同步

## 使用

- 本地 `.env` 配置 `CLOUD_SYNC_URL` 和 `CLOUD_SYNC_TOKEN`；线上 Worker secret 配置相同的 token。不要将密钥提交到 Git。
- 大数据同步使用独立轻量 Worker，共享同一 D1。设置 `CLOUD_SYNC_TRANSFER_URL` 为该 Worker 地址，`CLOUD_SYNC_URL` 仍指向工作台网站。传输端不加载 Next.js 或 Prisma，适配免费 Worker 的 10ms CPU 上限；未配置时兼容原工作台端点。
- 顶栏显示同步状态；设置页的“线上同步”可手动启动、查看上传数量、最近确认时间和错误。
- `POST /api/sync` 返回 HTTP 202 表示已排队，不表示线上已保存。`GET /api/sync` 的 `status: synced` 才表示已取得线上提交回执。
- 同步在本地 Node 服务后台运行，关闭浏览器不会取消。关闭本地服务会中断同步；重新启动后可再次发起。
- 以本地完整快照替换当前 Profile 的线上业务数据，不是双向合并。请避免同时编辑两端；同步前分别备份，备份文件不放入 Git。
- 没有数据变化的重复请求在当前进程内合并或跳过；重启后重新核验并上传。不将浏览器存储当作同步依据。

## 大备份处理

旧接口将完整 JSON 单次发送给 Worker。包含大量研究与新闻档案的备份可能超过 Worker 内存或 CPU 限制，返回 503；单纯延长请求超时无效。

新流程在本地复用完整备份校验和恢复规范化，但只捕获待写入行，不恢复或覆盖本地业务记录。普通请求最多 20 行、约 180 KB，最多两个并行请求。超过 128 KB 的单条记录再拆为不超过 24,000 个 UTF-16 单位的文本片段，避免切断代理对；每次最多传两个片段。超过数据库单行大小限制时明确报错，不截断资料。

线上 `/api/sync/transfer` 仅接受同步 token。分片写入私有 staging 表，校验表名、字段、归属、逐行摘要及关联；上传期间不修改业务表。最终检查完整快照摘要、线上变更及运行中任务，在一个 D1 batch 中完成替换和提交回执。失败整体回滚。

已上传的分片不可修改，可安全重复发送。大档案逐片校验 SHA-256，再校验有序分片摘要根；在 D1 内重组并通过 SQL 校验全部标量字段和归属，不将大档案完整加载至 Worker。提交后保留小回执并清理分片。提交请求响应不确定时先查询回执，不直接重复提交。未完成会话一小时过期，下一次同步启动时清理。新闻 API 已消耗额度按两端最大值保留，不因同步退还额度。

队列与运行记录沿用完整备份恢复语义：恢复为等待人工处理，不自动重新执行收费调用。同步不更改管理员登录、Worker secrets 或其他 Profile。

## 部署和恢复

1. 备份本地 SQLite、完整 JSON 和远端 D1。
2. 执行 `npm run cf:d1:migrate`，增量添加 `0019_cloud_sync_staging.sql` 和 `0020_cloud_sync_parts.sql`，不删除原业务数据。
3. 构建、运行 `npm run cf:deploy`。部署脚本会去除本地环境文件及其回退内容，避免密钥进入 Worker bundle。
4. 运行 `npm run cf:sync:deploy`，再用 `npx wrangler secret put CLOUD_SYNC_TOKEN --config cloudflare/sync-wrangler.jsonc` 为传输 Worker 设置同一个同步 token。将其地址写入本地 `CLOUD_SYNC_TRANSFER_URL`。不需要升级套餐。
5. 在本地启动同步，等待状态变为“线上已同步”，再核对远端记录。瞬时 5xx／429 只重试当前幂等分片，逐步退避，冲突或字段错误不重试。

若线上资料在上传期间变更，提交会拒绝；先保留该变更的备份，再重新发起。回滚业务数据使用事先导出的备份，程序代码回滚不能替代数据恢复。

当前没有双向冲突合并，也不保证页面没有触发保存同步的后台修改会立即上传；需要完整推送时使用设置页手动同步。

## 验证

`src/lib/cloud-sync-protocol.test.ts` 覆盖本地捕获不改源数据、完整提交、关联校验、分片幂等、摘要损坏、过期、运行中拦截、并发修改拦截、原子失败回滚、重复提交回执及新闻额度保留。

使用 `WORKSPACE_BACKUP_FILE` 指向本地私有备份可追加真实大备份隔离演练；测试不会写入实际业务数据库。

部署后可导出私有 D1 SQL，运行 `node --env-file=.env --import tsx scripts/verify-cloud-sync.ts <SQL文件路径> [本地SQLite快照路径]`，与本地关键表按 ID、业务字段及内容摘要比较，并检查数据库完整性与外键。可选快照用于逐条比对所有历史档案。历史 JSON 的兼容默认值仅在原有键值完全保留且新增值符合现有 schema 时接受，并单独计数。校验输出不包含个人资料原文；创建／更新时间及恢复后暂停的执行状态不作为内容一致性依据。
