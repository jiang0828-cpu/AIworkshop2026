信息采集页现在包含 11 个自动子栏目，以及“内部及其他／信息库”。后续分析、确认研判、应变与反馈沿用原流程。所有保存均为本地操作，不请求远端同步。

## 启动与配置

项目目录：`E:\AI\Codex\all in\03AI工作台\myaicube`。

服务端 `.env` 配置 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`、`TAVILY_API_KEY`。不要把密钥填写到栏目模板。修改环境变量后重启 Web 和调度器。

```powershell
npm run dev -- --hostname 0.0.0.0 --port 3012
npm run daily:worker
```

首次本地启用（自动备份 SQLite，再保存设置）：

```powershell
node --env-file=.env --import tsx scripts/enable-daily-news.ts
```

加 `--run-now` 会额外入队当下的 11 栏真实采集，产生服务商费用。不要在旧版调度器仍运行时初始化新任务。

默认每天北京时间 05:00 提前启动，以 07:00 前完成全部11栏采集和整理为目标，每日模型不超过36次。页面“栏目与时间”可编辑、启停。没有已保存的配置时保持暂停。电脑与调度器必须持续运行；恢复后只补当天缺失栏目。此功能由项目调度器运行，没有创建 Codex 聊天自动化。

本地地址：`http://localhost:3012/?section=situation`。局域网地址取本机 IPv4，端口 3012；需同一网络及防火墙允许。

## 执行与预算

### Windows 自动运行（2026-10-15）

已在本机注册 `MyAICube-LocalScheduler` Windows 任务：当前用户登录后启动，并每分钟检查调度器是否仍在运行；不会重复拉起已有的完整调度器。任务以当前用户普通权限、隐藏窗口运行，不保存密码或密钥。

```powershell
node --env-file=.env --import tsx scripts/enable-daily-news.ts --ready-by-seven
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-local-scheduler.ps1
Get-ScheduledTaskInfo -TaskName MyAICube-LocalScheduler
```

本地数据库已备份，时间改为 Asia/Shanghai 05:00，保留栏目模板和启停设置。07:00是完成目标，不再是开始时间。页面显示所选日期完成进度及逾时情况；服务故障不能保证按时成功，额度用尽保留可读原始报道，不虚报完成。恢复时只补当天缺失栏目。电脑须开机、保持唤醒、当前用户已登录且联网；锁屏可继续，关机或休眠期间无法执行。本机定时任务不替代远端服务。本次未部署或同步远端。

后台日志：`data/local-scheduler.log`、`data/local-scheduler-error.log`。暂停采集使用页面“栏目与时间”；Windows任务保活只恢复进程，不会强行重新启用已暂停的采集设置。停止Windows保活可运行 `Disable-ScheduledTask -TaskName MyAICube-LocalScheduler`。

DeepSeek 原生工具调用 → Tavily 公开搜索 → DeepSeek 检查覆盖并提出一次补搜／提取 → 最后一次模型整理。工具接口不支持时记录为结构化指令模式，兼容探测失败也计入模型次数。

每日每个 Profile 上限：80 次检索、20 页额外提取、36 次模型调用；每轮每栏最多 3 次模型调用、7 次搜索（时政 10 次）。11栏正常流程最多33次，新增3次额度优先用于补齐当天失败的最终整理；有未完成栏目时，手动全新采集会提示先补齐已有资料。前四次搜索为未完成栏目预留。先原子预占，再调用；服务失败也计入尝试，不能通过手动更新绕过。跨午夜的请求按实际调用日期占用额度，轮次仍保留最初截止时间。

每一步保存工具参数、来源 ID、用量和阶段。队列串行领取，租约 180 秒，模型超时 120 秒，检索超时 45 秒。进程或租约中断不自动重复计费，需人工重试。新轮次完成之前展示上一轮成功结果。

最终整理保留全部来源编号，正文摘录合计最多48,000字符、单条最多1,800字符；原始资料不截断保存。避免大量来源一次送入模型造成长时间等待，解读采用精简事实、影响和局限。

用户授权自动补齐后，模型HTTP 429／502／503／504或明确调用超时，当天已启用栏目在其他栏目首次处理结束后，等待60秒自动续跑最多一次；必须仍有本轮模型次数及当天剩余额度。超时请求可能已被服务商计费，该尝试与再次调用均保留计数，不退款或清零。租约中断、输出校验失败、历史日期和已停用栏目不自动重试。页面每5秒读取后台进度，关闭网页仍可继续。

2026-10-15起：最终整理遇临时HTTP错误或明确调用超时且本轮次数或自动续跑次数已用完，复用相同日期、截止时间和来源创建补齐轮次，只调用模型整理，不再检索。旧失败与用量不变，新请求仍占当天36次总预算，达到上限即停止。每日服务仍可能不可用，不能保证模型必然成功；无整理稿时页面保留原始报道分页及每条最多600字符的来源摘录供当日阅读，不把原始候选标成已核验资讯。

## 资料与引用

- 以采集轮次截止时刻前 24 小时为窗口；日期只有“日”而没有时刻，按时间待核实处理。旧事件归背景参考。
- 事实与 AI 影响解读分开。搜索摘要会标注“仅摘要”；原文、发布日期、事件日期和采集时间分别保存。
- 模型使用短来源编号，服务器映射回真实来源。逐条验证来源与连续摘录，拒绝无效候选并显示缺口，不凑足数量。
- 跨栏目来源按 URL／正文生成稳定 ID 保存到共享来源记录；每轮保留当时的来源摘录快照。转载归组，不等同于独立佐证。
- 不将个人档案自动交给检索或模型。内部资料只有用户选中、预览授权后才进入既有 AI 分析流程。
- “AI整理稿”不等于正式研判，选择资讯后仍需编辑分析并人工确认。

## 数据与恢复

使用现有 `RadarRecord` 保存 `newsConfig`、`newsRun`、`newsUsage`、`newsSource`；`ResearchBatch` 保存执行状态与日志。没有新增表或改动历史记录，因此此版本不需要新增 DDL；已有 SQLite／D1 必须先具有 `0010_external_radar.sql` 的表结构。

完整备份及模块备份包含栏目配置、轮次、来源、预算和日志；个人档案备份不包含这些外部资料。恢复后配置强制暂停，运行记录转为失败，等待人工重新启用或重试；旧备份没有栏目配置时继续暂停。

Cloudflare 复用 `cloudflare/daily-worker.ts` 的每分钟 Scheduled Handler；已提供构建和 dry-run 检查。远端 secrets、迁移和部署需另行确认，本次未执行。
