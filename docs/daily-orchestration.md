# 每日产出与 AI 协同编排

## 日常流程

1. 填写任务、预期产出、完成标准、期限与所需资料；也可选择已有行动。
2. 点击编排，模型判断重要和紧迫程度，生成可编辑的步骤与依赖。可选择引用当前场景今日已验收的结果。
3. 人工确认草稿。默认勾选保存后启动 AI，关闭该选项则只保存。保存与启动各有独立反馈，入队失败可以单独启动。
4. 无依赖的 AI 步骤并行运行，最多三个并发槽位。中间稿可自动供依赖步骤使用，不计入已完成任务；关键步骤可配置先人工验收。
5. 最终成果必须人工验收，现实操作和决策由本人完成。退回保留原因并重跑当前步骤。最终验收后，再确认回写关联行动。

AI 当前直接交付文本、分析、初稿及代码建议。没有联网、代码执行、外发、支付或发布工具；这些事项产出准备材料或建议，现实操作交由本人。

重要与紧迫程度分别保存，判断依据可以编辑。默认优先级为重要且紧迫优先，其次重要或紧迫，其余可延后；也允许人工调整优先级。列表先按优先级、再按截止时间排序。无法调用模型时明确显示规则编排，规则判断是待确认建议。

旧任务保留原有顺序与每步验收方式。尚未实际执行的任务可在详情中重新编排，确认后替换步骤并取消旧的未执行队列；已有运行、计时或产出记录的任务不能覆盖。完成记录和历史日志不自动转换。

## 本地运行

```powershell
npm run db:migrate:daily-orchestration
npx prisma generate --generator client
npm run dev -- --hostname 0.0.0.0 --port 3012
npm run daily:worker:tasks
```

调度器与页面独立，关闭浏览器仍可处理已启动任务。`daily:worker:tasks` 仅处理每日任务；既有 `daily:worker` 还处理研判队列。避免同时启动不必要的重复进程。模型超时与中断标为失败，需人工重试，不自动重复付费请求。

需要同时处理每日任务和手动研判，但暂不运行定时资讯时，使用 `npm run daily:worker:manual`。它处理用户已入队的研判及资讯作业，不创建定时资讯轮次；不会修改界面中保存的资讯配置。请只选择一个本地调度命令运行。

SQLite 迁移执行前自动完整备份，重复执行不重复加列。Cloudflare/D1 的增量文件为 `cloudflare/migrations/0012_daily_orchestration.sql`，部署和远端迁移需单独执行；本次未执行生产部署。

## 数据兼容

### 任务类型与业务归属

每日任务分为计划任务和临时任务，类型独立于 A/B/混合执行方式。新输入可选择类型、所属目标和项目；选项目时预填目标。确认新任务前必须补齐目标、项目，主场景可直接选择或在草稿中沿用关联记录。导入已有行动时默认计划任务，沿用原目标、项目和有效场景，不复制行动。

列表显示类型、场景及目标／项目名称，支持类型和“待关联目标／项目”筛选。任务详情可调整归属；关联原行动时须确认同步。历史缺少归属的任务继续显示待关联，原执行、计时和结果保留。独立每日任务的归属也显示在工作台，沿用现有去重规则。

类型及独立任务关联保存于现有编排 JSON 的 `affiliation`，不增加数据库迁移。行动的目标、项目仍以原行动为准，跨模块修改后重新读取即更新。接口检查 Profile、目标／项目关系，关联写入与任务保存使用 SQLite 事务或 D1 batch；完整备份和同步包含新信息。关联对象删除后保留任务、以待关联展示，不自动生成目标或项目。

新增 `DailyTask.orchestration` JSON 字段保存重要程度、紧迫程度、判断依据、预期产出，以及各步骤的用途、依赖与验收要求。空配置表示旧版顺序执行。

每日协同 JSON、完整备份和同步包含该字段。旧备份缺少字段时按旧版顺序恢复；恢复的待执行、排队和运行步骤暂停，需手动重新启动，不自动发起模型调用。新草稿保存使用请求编号防重，SQLite 事务与 D1 batch 保证任务和步骤完整保存；最终验收同样原子保存。

## 本次验证

### 人性化时间匹配

新增建议开始和完成时段，与业务截止时间分开保存。编排草稿自动匹配，调整场景、优先级、耗时或步骤时重新匹配；手动安排保留。已有未完成任务可通过“安排时间”先预览再确认，不启动任务，不改变执行状态、计时或成果。

默认按上海时区：工作使用工作日白天，沟通优先下午；家庭优先 19:00–21:00，爱好优先 20:00–22:00，健康优先早晚。预约类事项使用工作日营业时段并提示确认。高优先事项先分配，紧急期限可使用其他白天时段。避开午休与已保存安排，正在运行的人工计时也预留剩余时间；任务间保留 10 分钟空档。AI 准备可重叠，人工验收不重叠。

容量不足时在未来 7 天寻找时段并提示顺延；截止前无空档或任务过长时不伪造准时安排，要求调整或拆分。默认时段只是建议，个人真实日程及营业预约需要手动核对。建议保存在现有编排 JSON 的 `schedule` 中，无需新数据库迁移，完整备份和同步沿用原字段，旧任务执行顺序不变。
