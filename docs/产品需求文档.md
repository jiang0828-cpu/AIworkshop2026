# AI 工作台产品需求文档

文档日期：2026-10-15。产品版本：`0.1.0`。代码基线：`72bb9e5`。

本文依据当前程序描述已实现的产品能力，供产品维护、功能验收和后续迭代使用。历史建设方案与本文不一致时，应结合实际代码核实，不将规划功能视为已交付功能。

相关文档：[技术文档](技术文档.md) · [使用说明](使用说明文档.md) · [项目入口](../README.md)。

## 1. 产品定位

AI 工作台是面向个人的规划、执行与复盘工具，将个人认知、外部信息、目标项目和人机协作连接到同一套业务记录。

核心主线为：

```text
认识自己与环境 → 总愿景/场景愿景 → 目标 → 项目 → 任务
       ↑                                   ↓
       └──── 更新能力与资源 ← 复盘 ← 结果与人工验收
```

允许直接创建行动或临时任务，无需先补齐档案、愿景、目标和项目。AI 用于整理资料、形成草稿和完成文本工作；选择、保存、验收及业务回写由用户确认。

### 1.1 目标用户与需求

| 需求 | 产品回应 |
| --- | --- |
| 想法多，难以转为行动 | 从愿景拆出需求、目标、项目及任务草稿 |
| 个人信息、任务和 AI 结果分散 | 共享来源关联和业务记录，减少重复录入 |
| 不清楚今天做什么 | 工作台优先事项、待处理任务和交付提醒 |
| AI 结果缺少验收 | 后台执行、步骤进度、人工验收及确认回写 |
| 复盘依赖手工回忆 | 按交付时间汇总计划，按实际完成时间补充成果 |
| 数据难以迁移 | SQLite/D1、JSON 备份和 Markdown 产物 |

### 1.2 设计原则

- 操作轻量：必要字段优先，详情按需展开，不要求逐级填写。
- 数据可信：场景按关联继承，任务按 ID 去重，未知资料不当作事实。
- 人工可控：AI 内容进入可编辑草稿，明确启动后执行，验收通过才计完成。
- 连续使用：记录可打开原来源，跨模块复用，历史版本可查。
- 本地优先：本地数据与云端数据分别保存，代码备份不替代业务备份。

## 2. 信息架构

| 一级模块 | 内部组成 | 核心产物 |
| --- | --- | --- |
| 我的工作台 | 任务列表/看板、场景概览、今日优先、近期动态 | 今日推进清单 |
| 每日任务协同 | 今日任务、Agent 管理、每日复盘 | 执行结果、验收记录、日报 |
| 形势研判 | 信息采集、信息分析、形势判断、决策应变 | 有来源的判断与应对草稿 |
| 目标与执行 | 目标→项目→任务、规划与对齐、全部任务 | 可交付的项目及任务体系 |
| 任务与复盘 | 周、月、年计划与复盘 | 当期计划、上期总结 |
| 认识自己 | 个人档案、我的愿景、我的能力、我的资源、项目及经历 | 认知记录、需求、能力证据 |
| AI 档案中心 | 档案中心、AI 使用中心 | Markdown 档案、上下文、协作说明 |
| 设置 | 配置状态、偏好、隐私、备份与同步相关操作 | 运行配置与数据管理 |

旧决策中心入口兼容跳转到“目标与执行”，不再作为独立主模块。

## 3. 场景与归属规则

当前默认七个场景：健康、财务、工作、家庭、爱好、其他、系统。其中“系统”用于工作流、工具和系统维护；总愿景是独立记录，不是一个场景。

- 场景可改名、排序；稳定 ID 和永久槽位保持历史关联。
- 目标、项目、行动和独立每日任务各有一个主场景。
- 行动明确指定场景时优先使用；否则依次继承项目、项目所属目标、直接关联目标，最终回退“其他”。
- 手动指定后的归属不随上游改变；不按标题自动猜测。
- 已有行动导入每日协同时沿用原行动归属，修改场景须明确同步原行动。
- 个人档案、经历和证据的适用场景允许多选；未选择表示“全局”，不强制归入“其他”。

列表、详情、草稿和筛选应使用一致的场景标签。历史四/五/六场景数据恢复时补齐缺失项，保留原有 ID 和内容。

## 4. 功能需求

### 4.1 我的工作台

统一展示行动和每日任务，支持列表/看板、搜索、场景、状态和来源筛选。关联同一行动的记录按 ID 去重，步骤进度来自实际执行数据。

今日优先最多三项：手动置顶优先；其他候选依次考虑待验收、阻塞/失败、逾期、今日截止，再按优先级及截止时间排序。置顶按上海日期保存，完成事项退出推荐。

场景概览展示目标、活跃项目、待推进及需处理数量。近期动态可打开对应来源，不生成无事实依据的全局综合评分。

### 4.2 认识自己

| 页签 | 记录内容 | 应用方式 |
| --- | --- | --- |
| 个人档案 | 当前阶段、角色、性格特征、优先事项及场景资料 | 为规划和 AI 提供可选择的个人背景 |
| 我的愿景 | 总愿景；场景主要目标、期望状态、衡量标准、时间范围、底线 | AI 拆解场景愿景，安排第一步 |
| 我的能力 | 能力需求、重要性、自评、证据、补齐渠道和推进状态 | 根据愿景分析缺口，确认录入统一能力库 |
| 我的资源 | 可用资源、数量/条件、限制、假设和需求匹配 | 安排使用、验证和资源补齐行动 |
| 项目及经历 | 做过什么、结果、学到什么 | 沉淀为能力证据，支持后续规划引用 |

AI 支持分类、整理、完善和思考，依据选择的资料输出草稿。能力自评可留空；需求不等于已具备能力，缺少证据时应明确提示。

轻量闭环：来源记录安排行动或关联已有行动 → 更新进度 → 完成人工行动 → 填写“实际结果”和“下次调整” → 选择补证据、更新原记录或暂不更新。复盘归属于同一个行动，多来源共享；确认回写防止重复创建。

愿景及其他认知记录不因 AI 生成或行动完成而自动修改。五个页签支持对应范围的 JSON 导入导出。

### 4.3 形势研判

围绕“采集 → 分析 → 判断 → 应变”处理外部环境。记录事实、来源、日期、核验状态、分析和影响，并保留判断版本及变化记录。

每日资讯可使用 DeepSeek 与 Tavily 获取、整理有真实来源的内容，依赖服务端配置、调度器、预算和网络。定时触发不代表保证在指定时刻完成。

低置信度内容先核验。研判转为目标、任务或决策时先预览草稿，确认后保存关联；不自动执行现实操作。

### 4.4 目标与执行

保留父子目标、多级项目/任务、里程碑、交付编号、截止时间、风险、边界、投入和停止条件。项目行动完成率与里程碑状态分别表达。

“规划与对齐”引用愿景与研判，维护重大决策、选项比较和目标关系。促进、冲突、依赖须有依据；禁止自关联，冲突对称、依赖有方向。对齐检查展示具体问题，不虚构评分。

AI 系统规划流程：

1. 填写四周起点、可用时间、预算及其他现实约束。
2. 预览所选资料，确认敏感资料授权。
3. 生成目标、项目、任务草稿，调整新增、复用和更新项。
4. 完成 AI 复核及规则校验，包括容量、依赖和底线。
5. 人工确认后原子保存，再选择任务加入每日协同。
6. 在每日协同明确启动执行。

未知条件允许暂缓；修改草稿后重新校验。过期草稿不得覆盖新数据，重复确认不得重复创建，保存不自动启动任务。

### 4.5 每日任务协同

输入支持自由文本、已有行动及临时任务。编排生成可编辑的分类、优先级、完成标准、步骤、执行人、依赖、耗时及检查点；确认保存后仍需手动启动。

- A 线：本人执行，支持开始、暂停、继续、完成和持久化计时。
- B 线：AI 文本任务，队列执行并保存独立输入、配置、输出、耗时和错误。
- 混合：人工与 AI 步骤按依赖推进，独立的 AI 准备步骤可并行。
- 人工验收：AI 产出不等于完成；可接受或退回并填写要求。
- 行动回写：任务完成后显式确认同步原行动；周期行动只记录本次执行，不结束主任务。

同日导入同一行动不重复创建。后台最多同时运行三个 AI 步骤；关闭浏览器后仍可执行，前提是本地调度进程或云端定时 Worker 持续运行。

Agent 管理支持角色、模型、提示词、启停、超时及 Tool/Skill 指引。每日执行器目前支持文本模型，代码 Agent 输出代码与建议；自定义 Tool/Skill 不等于已接入真实代码执行、联网搜索或任意外部 Agent。

日报默认上海时间 22:00 保存，停机后补缺失日期，保留人工反思；支持手动生成和 Markdown 导出。

### 4.6 周、月、年计划与复盘

每个周期页签仅突出两个区块：当周/当月/当年计划，以及上周/上月/去年总结。默认进入上海当前周期，支持手动日期和历史查看。

- 当期计划按项目、里程碑和行动的交付日期自动整理。
- 上期总结结合应交付事项和实际完成的行动、每日工作。
- 普通成果按实际完成时间归期；周期计划次数按每日计划日期核对。
- 同一行动按 ID 合并；同名但不同 ID 的任务不合并。
- 按场景分类，可折叠、筛选；允许独立每日工作参与复盘。
- 自动内容是可编辑草稿，允许增删改；保留人工填写和主动清空的内容。
- 主动重新填充覆盖前确认，历史已保存总结不随当前业务变化自动重写。

周期任务复用一个主行动，每日只生成该日执行记录，仍需确认编排及启动。周重复锚定创建星期，月重复锚定创建日、短月取月末；结束日期含当天。手动完成、取消或归档主行动后停止后续执行。

### 4.7 档案、AI 使用和数据管理

档案中心生成五份 Markdown 档案，支持编辑、版本、差异比较和 ZIP 下载。AI 使用中心维护身份卡、上下文包、AI 任务、任务反馈及纠正记录。

AI 使用中心的任务清单用于组织协作说明和提示词，不是自动后台执行器。L1–L4 表示应用内确认规则，不授予外部账户或工具权限。

完整 JSON 备份覆盖业务数据；个人档案备份只覆盖相应档案及证据，不复制目标、项目、行动和行动复盘。导入属于对应范围恢复/替换，应先备份，不默认视为合并。

## 5. 关键数据与状态要求

1. 同一 Action 在工作台、执行和复盘中共享身份；DailyTask 是某日执行记录，不替代主行动。
2. 来源删除保留业务记录和复盘，显示来源已删除，不级联清空历史。
3. AI 草稿、已保存任务、执行产出、验收通过是不同阶段。
4. 计时来自服务端记录，刷新页面不从零开始；AI 耗时累计调用耗时，不等同于并行执行墙钟时间。
5. AI token 缺失时显示未知，不估算冒充服务商返回数据。
6. 超时、中断和租约过期等待人工重试，避免不确定请求自动重复计费。
7. 运行中任务禁止覆盖导入；恢复的排队或运行记录需人工重新启动。
8. 上海时间统一用于每日边界、置顶和周月年周期，周一为一周起点。

每日效率得分仅用于每日协同：完成率权重 60%、准时率 25%、未曾阻塞比例 15%；无适用准时项时重新归一化，无任务不评分。准时率统计有截止时间且已到期或已完成的任务。

## 6. 非功能需求与边界

- 本地 SQLite、云端 D1 共用业务模型；迁移保留已有 ID 和记录。
- 线上页面及业务 API 需认证；所有关联校验当前 Profile 归属。
- 当前使用固定单 Profile，不是完整多租户系统。
- API key 仅在环境变量或 Worker secrets，不进入浏览器、业务日志及备份。
- AI 请求先选择资料并处理敏感授权；上下文快照与历史文档不追溯改写。
- 桌面列表/详情与手机单列/抽屉保持流程一致；长内容支持折叠。
- 未接入的语音输入、效率热力图、通用图片/PDF 报告导出和真实代码执行不作为已实现能力。

## 7. 核心验收场景

| 场景 | 预期结果 |
| --- | --- |
| 愿景生成能力与资源需求 | 草稿可编辑、筛选确认，取消不写入正式记录 |
| 愿景→目标→项目→行动→每日执行 | 关联和场景一致，无重复行动，启动需明确操作 |
| AI 执行并关闭页面 | 后台仍运行，重开可看产出，验收前不计完成 |
| 退回 AI 结果 | 保存退回要求并产生新执行，旧响应不能覆盖新结果 |
| 当期计划与上期复盘 | 日期归属正确，包含独立每日成果，按 ID 去重 |
| 行动完成后补证据 | 人工确认回写，多次点击不重复创建 |
| 场景改名与旧备份恢复 | 历史关联保留，缺失默认场景补齐 |
| 导入含运行记录的备份 | 当前运行时拒绝覆盖；恢复后等待人工重新启动 |

验收表是后续回归标准，不代表本文编写时重新执行了全部流程。最近发布验证及其限制见[发布记录](deployment-2026-10-15.md)。
