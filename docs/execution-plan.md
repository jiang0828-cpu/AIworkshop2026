# AI系统规划

入口：目标与执行 → 规划与决策 → AI系统规划。沿用当前 Profile、六场景与已有每日协同，没有新增独立任务库。

## 操作

1. 填写四周起始日期、每周实际可用小时、可安排日期、90天金额上限。未知允许留空，不能当作已具备。
2. 预览实际发送资料，逐项展开查看。敏感内容须按现有授权机制授权，联系方式与证件信息脱敏。已确认研判可选加入，不联网。
3. 确认发送，DeepSeek生成长期目标、90天项目及近四周任务的独立草稿。
4. 展开目标、项目、任务编辑；选择新增、复用或更新原记录。更新须勾选字段差异，状态、已有成果、复盘与历史证据不覆盖。
5. 调用DeepSeek复核价值、底线和现实条件。规则额外检查容量、日期、依赖与重复事项。修改后校验失效，必须重新校验。
6. 处理校验问题：明确底线违规须修改或排除；未知条件暂缓，记录核实事项；推断冲突可填写理由后人工核对。确认保存采用原子操作和幂等防重。
7. 保存后选择符合条件的任务加入每日协同，再在每日协同明确启动。人工计时、AI结果验收、行动回写和复盘继续使用原流程。

资料变动后先刷新差异，再校验确认；过期草稿不能覆盖当前记录。保存失败保留页面输入。URL的 `planId` 可定位和恢复草稿；离开未保存页面提供保存、放弃、继续编辑。

暂缓任务须记录实际核实结果。未确认时间、日期或金额的规划，须先补充条件重新规划，不能仅凭“已核实”绕过。执行检查按整周累计已有每日任务，前置行动必须真实完成并确认回写。已启动步骤可继续和完成，不因越过排期窗口丢失成果。新批次重新确认复用行动后按最新批次执行，旧批次仍保留历史。

## 本地与迁移

环境变量沿用 `DATABASE_URL`、`AI_API_KEY`、`AI_BASE_URL`。规划使用 `deepseek-reasoner`，密钥不会保存到快照、浏览器或备份。模型调用最长120秒，租约180秒；超时/中断须手动重试，无自动重复付费调用。

```powershell
npm run db:migrate:execution
npm run dev -- --hostname 0.0.0.0 --port 3012
npm run daily:worker
```

迁移脚本先通过 SQLite `VACUUM INTO` 备份数据库，再增量创建 `ExecutionPlan`，不会修改历史档案或业务数据。重复运行不会重复建表。修改模型后正常运行 `npx prisma generate`；Windows下更新客户端前应结束持有旧Prisma引擎的本地服务，再重新启动。

DeepSeek生成由服务端请求执行，本地服务进程运行时，关闭页面不会主动取消模型调用，草稿可从历史恢复。云端请求可能受平台生命周期影响，中断后等待租约结束并由用户重试。已导入的每日AI任务依靠独立调度进程运行，不依赖浏览器轮询。实际规划调用不会启动每日任务。

## Cloudflare与备份

增量迁移文件：`cloudflare/migrations/0011_execution_plan.sql`。部署时应先备份D1，审核并应用现有迁移链，再部署包含新API的应用；每日执行仍使用原定时Worker。本次未部署生产、未执行远端迁移。

完整备份和同步包含规划批次。旧备份缺少批次仍可恢复；个人档案备份不复制执行规划。运行中拒绝覆盖导入；备份恢复中的生成/校验调用改为中断，等待人工重试，绝不恢复旧租约或自动调用模型。
