# 总愿景与六场景

在“认识自己 → 我的愿景”顶部填写总愿景及重要底线。下面依次为健康、财务、工作、家庭、爱好、其他，每个场景可填写一份当前愿景，并保留历史及安排行动入口。总愿景在决策中心只读展示，编辑回到认识自己。

## 场景如何传递

- 子目标默认沿用父目标；项目新建时默认沿用目标。跨场景项目需确认。
- 行动手动指定场景优先；未指定则跟随项目（包括项目的目标），其次跟随直接关联目标，最终归入“其他”。编辑行动可恢复“跟随项目／目标”。
- 从场景愿景安排行动预填场景；档案记录有唯一适用场景时预填，多场景时自行选择。
- 每日协同导入行动使用同一条行动的场景，不复制分类。修改时需要确认同步原行动，各日期的关联任务和工作台一起变化。
- 独立每日任务保存自己的场景。编排优先使用当前筛选场景，AI 的建议只进入草稿，确认后保存；未知归入“其他”。
- 工作台、目标项目、行动和每日协同均显示场景并支持筛选。每日顶部显示各场景任务数量。个人档案适用场景仍可多选，未选为全局。

“职业”沿用原 ID 并改名为“工作”，新增“爱好”。“理想国”不再作为分类。未分类旧业务数据保留原字段，通过统一的有效场景解析显示为其他；不根据标题猜测归属。更改场景名称与排序不会改动历史关联。

## 数据与接口

- `StrategyRecord.kind=overallVision` 保存每个 Profile 唯一的总愿景，版本继续使用 `StrategyVersion`。
- `Action.sceneId`、`DailyTask.sceneId` 为可选场景字段；关联行动的 DailyTask 不保存第二份场景。
- `/api/data` 为目标、项目、行动返回 `effectiveSceneId`、`sceneSource`；每日接口返回相同字段及 `scenes`、`sceneCounts`。
- `/api/strategy` 原记录保存接口支持总愿景；每日编排草稿支持 `sceneId`，关联行动的每日任务更改场景需 `confirmActionScene=true`。
- 完整备份、同步、个人档案备份、Markdown、AI 上下文支持六场景及总愿景。个人档案备份仍不复制行动；旧四／五场景备份恢复时补齐场景，保留原 ID 和历史内容。

## 迁移与启动

```powershell
npm run db:migrate:scenes
npx prisma generate
npm run dev -- --hostname 0.0.0.0 --port 3012
npm run daily:worker
```

Windows 生成 Prisma Client 前需停止使用原生引擎的预览／调度进程，生成后再启动。迁移脚本先用 `VACUUM INTO` 备份 SQLite，再原子执行 `cloudflare/migrations/0007_six_scenes.sql`，重复执行会跳过。本地数据库已完成备份迁移。

Cloudflare 使用同一增量 SQL；部署时先备份并迁移 D1，再部署应用。本次只进行本地 D1 验证，不执行远端迁移或生产部署。
