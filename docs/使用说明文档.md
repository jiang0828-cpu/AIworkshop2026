# AI 工作台使用说明

更新日期：2026-10-15。适用于当前 `0.1.0` 版本。

本文帮助日常操作；安装、迁移和部署细节见[技术文档](技术文档.md)，功能范围见[产品需求](产品需求文档.md)。下文示例均为虚构内容。

## 1. 进入工作台

- 线上：<https://ai-workbench.jianghaohan0828.workers.dev>，使用管理员配置的账号登录。
- 本机预览：<http://localhost:3012/>，需要本地网页服务正在运行。
- 当前局域网地址：<http://10.5.2.31:3012/>，设备须在可互通网络内；电脑 IP 改变后地址也会变化。

本地和线上数据库分别保存。切换访问地址前先确认数据来源，不要把另一套数据库中的空白或旧资料误认为数据已丢失。

## 2. 第一次使用：先走一条最短流程

1. 进入“认识自己 → 我的愿景”，写一个想达到的状态及完成标准。
2. 选择场景，点击安排第一步，创建或关联一条小行动。
3. 进入“每日任务协同”，导入该行动，检查编排草稿并确认保存。
4. 手动启动；本人步骤完成后记录结果，AI 步骤产出后人工验收。
5. 完成后确认同步原行动；返回来源填写简短复盘，选择是否补充能力证据。

不必填完整档案才能开始。当天的临时事项也可以直接在每日协同创建。

## 3. 场景怎么选

| 场景 | 典型内容 |
| --- | --- |
| 健康 | 作息、运动、身心状态 |
| 财务 | 收支、储备、保障 |
| 工作 | 职业发展、业务产出 |
| 家庭 | 关系、陪伴、家庭事务 |
| 爱好 | 兴趣、阅读、创作 |
| 其他 | 不属于上述类别的事项 |
| 系统 | 工具、流程和工作台维护 |

每条业务记录选一个主场景；总愿景不属于第八个场景。场景可改名和排序，历史关联仍保留。

新项目通常跟随目标，新行动通常跟随项目或目标；没有关联时默认其他。明确手动选择后，上游改变不会覆盖它。每日协同中的关联任务沿用原行动场景，修改时注意同步提示。

个人档案和证据的“适用场景”可多选，不选就是全局。全局资料在全部场景中查看，不会自动归入其他。

## 4. 认识自己：记录变成行动

### 4.1 个人档案

先填写当前阶段、角色、优先事项和性格特征，详细背景按需补充。场景资料用于表达在不同生活领域的现实状态，不必把同一段经历复制到各处。

示例：“目前主要做产品协调，擅长书面整理，希望改善会议表达；未来四周每周可练习两小时。”

个人情况变化时修改当前记录；不确定的判断保留为假设，避免把 AI 推断当作已确认事实。

### 4.2 我的愿景

总愿景写整体方向和重要底线；场景愿景写具体内容：主要目标、期望状态、衡量标准、大致时间和底线。长内容可折叠查看。

示例：

```text
场景：健康
主要目标：建立稳定运动习惯
期望状态：工作日也能保持体力与规律作息
衡量标准：每周完成三次适合自己的运动并记录感受
时间范围：未来四周先试行
底线：不因训练影响休息，有不适及时调整
```

需要 AI 时，选择总愿景和必要背景，使用愿景拆解/规划入口。查看各场景草稿，补充或删除不合适的推断，手动确认后才更新正式愿景。取消不会把草稿写进正式记录。

点击“安排第一步”时，只写行动名、完成标准和可选日期即可。已有未完成行动时优先继续，不重复新建。

### 4.3 我的能力

能力库统一管理“需要什么”和“已经有什么”。可以手动记录，也可根据愿景的主要目标、指标和时间让 AI 分析需求。

操作顺序：

1. 先确认愿景内容足够具体，再选择相关资料进行能力需求分析。
2. 查看已有能力匹配与缺口，按关键、重要、一般调整重要性。
3. 删除重复、无关或超出当前阶段的建议，确认纳入能力库。
4. 为已具备能力补证据；为缺口选择实战、拜师、阅读、工具或组合渠道。
5. 安排一次练习，完成后把实际结果沉淀为证据。

示例：“需要表达能力”过于宽泛，可改为“十分钟内讲清项目进展、风险和待决事项”，再安排一次真实汇报练习。自评分可不填，需求录入不代表能力已掌握。

### 4.4 我的资源

记录有什么可用、可用多少、使用条件及限制。AI 可按愿景匹配现有资源、整理缺口，再由你筛选录入。

示例：“每周有两小时练习时间；可使用一门已购买课程；同事愿意每两周反馈一次。”

区分现有资源、尚需补齐的资源、限制和待验证假设。通过“安排使用/验证”形成小行动，不将模型估计的资金、人脉或时间当成真实拥有。

### 4.5 项目及经历

按“做了什么 → 结果 → 学到什么”填写，证据可引用实际产物或反馈。使用“沉淀为能力证据”后检查预填内容，确认保存，避免把同一经历再手抄为另一份记录。

### 4.6 完成一次轻量闭环

来源记录下可查看关联行动并更新进度。同一行动在其他模块完成后，重新进入或恢复窗口焦点时会刷新；有未保存输入时先处理当前编辑。

完成人工行动后填写“实际结果”和“下次调整”，实际结果必填。已有每日协同结果可引用。保存复盘后选择：补充能力证据、更新原记录，或暂不更新；检查草稿并确认，才会回写。再次操作可查看已处理结果，不重复生成证据。

AI 行动必须先走人工验收及原有回写，不能通过这里提前跳过验收。

## 5. 形势研判：信息变成依据

1. 在“信息采集”添加资料、观察或查看配置启用的每日资讯。
2. 保留来源、日期及核验状态，事实与个人判断分开。
3. 在“信息分析”整理关联、影响和不确定点。
4. 在“形势判断”确认当前判断，保留历史版本。
5. 在“决策应变”形成应对，按需转为目标、行动或决策草稿。

先核验低置信度内容。AI 资讯需要模型、检索服务和后台支持；有链接也应检查来源是否真正支持结论。转为业务记录前先预览确认，不会自动替你作出重大选择。

## 6. 目标与执行：把方向变成可交付事项

### 6.1 手动建立目标、项目、任务

- 目标说明要达到什么、如何衡量和何时完成。
- 项目说明要交付什么，补充截止时间、边界、里程碑、风险和停止条件。
- 任务说明下一步具体做什么、完成标准和交付日期。

示例：目标“提升汇报质量” → 项目“完成四周汇报训练” → 任务“整理一次项目汇报提纲”。

在“目标→项目→任务”查看连续关系，在项目详情添加任务、里程碑或加入每日计划。“全部任务”用于集中查找；不属于项目的独立任务可直接创建。

任务有了准确交付日期，周月年计划才能自动归入正确周期。界面预计投入使用分钟填写，不必自行换算底层存储单位。

### 6.2 使用规划与对齐

查看愿景、研判及重大决策，处理缺指标、缺日期、场景不一致或已记录冲突。愿景需要修改时返回认识自己，避免维护两份内容。

AI 系统规划前先写可用时间、预算和约束，选择必要资料，预览授权后生成。逐项检查目标、项目和任务，选择新增、复用或更新；通过复核与规则校验，再确认保存。修改草稿后重新校验。

保存只形成业务记录，不会立即调用 AI 执行。选择任务加入每日协同后，还要确认编排并启动。

## 7. 每日任务协同：启动与验收

### 7.1 从输入到执行

1. 确认日期和场景，输入待办，或导入已有行动。
2. 点击编排，查看 A 本人、B AI、混合分类，调整步骤和完成标准。
3. 检查每步执行人、前置依赖、时间和检查点，确认保存任务。
4. 点击单项启动或批量启动；保存不等于启动。
5. 人工步骤由你完成，AI 步骤由后台按依赖领取执行。

同日重复导入已有行动不会复制一份行动。独立 AI 准备步骤可并行；后续需要人工判断的步骤仍等待你处理。

### 7.2 人工计时与阻塞

开始、暂停、继续和完成使用服务端计时，刷新后保持记录。遇到阻塞时填写原因和需要的帮助，解除后继续。计时和预计时间是不同指标。

### 7.3 AI 怎么启动工作

先确认设置中模型配置可用，Agent 已启用，任务含 AI 步骤，并且本地后台或云端调度器正在运行。随后启动任务，等待排队、运行和待验收状态。

AI 产出后阅读结果：符合完成标准则验收；不符合则退回，填写具体修改要求。失败或中断先看错误，再人工重试，不连续重复点击。

编码 Agent 输出代码和建议，不会直接修改你的外部项目；工具/技能提示不代表已经获得真实联网、代码执行或外部账户权限。形势研判的联网资讯是另一套已配置功能。

完成任务后若有关联行动，点击确认同步完成。周期行动仅记录这一次执行完成，下一次仍可继续；要停止后续，需手动结束主行动。

### 7.4 离开页面后

关闭浏览器不会自动停止后台。本地电脑需保持开机、不休眠、联网，并持续运行网页与调度器；云端依赖独立定时 Worker。可在页面查看最近心跳。

Agent 日志展示输入、输出、耗时和错误。token 未返回时显示未知。日报可手动生成，默认上海时间 22:00 保存，重启后补缺失日期。

## 8. 周、月、年计划与复盘

进入“任务与复盘”，选择周、月或年。默认当前周期；上方计划对应当周/当月/当年，下方复盘对应上周/上月/去年。周从周一开始。

计划优先从项目、里程碑、任务交付时间自动整理；复盘还包含上期实际完成的每日工作，按场景展示。同一行动自动去重，同名不同记录不会合并。

你可以调整自动草稿、手动增删记录或填写总结。已经写过或主动清空的内容会保留；需要重新按业务记录填充时，确认是否覆盖。已保存历史不会随当前项目变更自动重写。

建议复盘只回答三件事：实际交付了什么、为什么偏差、下期改变什么。没有项目的独立每日成果也可以纳入，不必为复盘临时补造项目。

周期任务显示应执行和已完成次数。月末日期会按实际月份调整；修改重复规则后，当前计划按新规则计算，历史已保存总结保持原样。

## 9. 档案与 AI 使用中心

档案中心适合生成、编辑、比较和下载 Markdown 档案；需要可读资料时导出单文件或 ZIP，需要恢复整个应用时使用完整 JSON。

AI 使用中心流程为：身份卡 → 选择资料形成上下文包 → AI 任务说明 → 复制/下载给 AI → 记录反馈 → 确认纠正。身份卡草稿需确认成为当前版本。

此处的“AI 任务”是协作说明，不是自动执行开关。需要模型后台运行时进入每日协同。权限级别不会授予第三方账户访问权限。

## 10. 导出、导入和同步

重要编辑或恢复前先备份当前数据：

| 需要 | 使用方式 |
| --- | --- |
| 完整恢复工作台 | 完整 JSON 备份，另保留数据库快照 |
| 迁移认识自己的某个页签 | 对应页签 JSON 导入/导出 |
| 分享可阅读资料 | 检查敏感内容后导出 Markdown/ZIP |
| 保存一天复盘 | Markdown 日报 |
| 备份程序 | Git，不包含个人业务库和密钥 |

导入会恢复/替换对应范围，不默认追加合并。先核对文件类型与范围，再确认操作；有运行中任务时先处理任务。恢复的排队或运行任务不会直接继续，需检查后人工启动。

个人档案备份不复制目标、项目、行动和行动复盘。同步是否启用取决于管理员配置；切换本地与云端后先确认访问地址和数据，避免用旧备份覆盖较新的记录。

## 11. 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 个人档案看起来不见了 | 先看网址是本地还是线上、场景筛选是否限制范围；不要立即导入覆盖，先导出现状并核对备份 |
| AI 按钮报错 | 检查服务端配置、模型和网络；保留草稿后重试。不是所有功能都有规则回退 |
| 任务一直排队 | 查看后台心跳、Agent 启用状态、前置步骤和三个并发槽位是否占用 |
| 任务失败或中断 | 查看错误，确认是否已有产出，再人工重试；重试可能产生新的模型费用 |
| 已有结果但未完成 | 检查是否仍待人工验收、还有后续步骤，或未确认同步行动 |
| 计划没有自动出现事项 | 检查周期、场景及交付日期；周期行动还要检查开始锚点和结束日期 |
| 复盘出现重复名称 | 比较记录 ID 和关联来源，同名可能是不同任务；同一行动优先复用 |
| 改了任务但其他页未更新 | 先保存，再重新进入或恢复页面焦点；先处理未保存编辑 |
| 局域网打不开 | 检查服务监听 0.0.0.0、电脑当前 IP、同网可达性和防火墙 |
| 导入被拒绝 | 核对备份范围、格式、运行任务和归属；不要直接手改数据库绕过校验 |

## 12. 管理员启动附录

已安装并完成配置时，在项目目录运行：

```powershell
npm run dev -- --hostname 0.0.0.0 --port 3012
```

另开终端运行：

```powershell
npm run daily:worker
```

端口被占用时先确认现有服务用途，再选择其他端口并使用新地址。全新安装、旧库升级、云端迁移及发布请参照[技术文档](技术文档.md)，不要在有数据的库上无备份试运行初始化或完整导入。

网页能打开只表示前端服务可访问；AI 可调用、调度器有心跳、任务已验收和数据已备份是不同事项，应分别确认。
