# 基础档案的场景资料

基础信息（称呼、年龄、城市、学历、专业和性格特征）仍为全局资料。
当前身份、人生阶段、现实情况可以在健康、财务、工作、家庭、爱好、其他中分别填写，均为可选字段。

三个板块的参数随场景适配：健康使用作息、精力与恢复条件；财务使用收支、预算与保障；工作使用岗位、交付与协作；家庭使用角色、分工与陪伴；爱好使用兴趣、练习与作品；其他使用具体事项、进展与约束。
每个场景有对应的阶段候选和填写示例，仍可自由填写个人阶段，不按年龄或资料自动判定，也不默认填写金额、评分或指标。
之前在单个场景里填写的通用字段保存在“原有场景资料”，继续可查看和编辑，不将旧内容直接换名称或自动推断到新字段。

原有三组内容保留在“全局 / 原有资料”。不自动猜测分类，也不复制到六个场景。
页面的场景筛选可直接打开相应场景；全部场景下可在“场景档案”下拉框切换。
切换保留未保存输入；保存提交所有已修改的场景，失败保留输入。
基础信息与场景档案分别保存，离开页面时沿用未保存保护。

## 存储与兼容

- 复用 `StrategyRecord` 的 `profileScene` 类型和 `StrategyVersion` 历史，按当前 Profile 和稳定场景 ID 保存一份资料。
- 适配参数保存于原记录的 `sceneDetails`；稳定场景槽位决定表单与参数校验，场景改名或排序不改变字段含义。
- `/api/strategy` 的 `profile-scenes-save` 校验所有场景后原子保存全局资料、各场景资料和版本；SQLite 使用事务，D1 使用 batch。
- 无数据库结构变更，无需执行迁移，不修改现有个人信息或生产数据。
- 完整备份、同步、个人档案板块备份和 Markdown 导出包含场景档案；旧备份缺少场景档案仍可导入。
- AI 规划和价值提炼可以引用场景资料，继续遵守原有敏感字段授权及场景授权。新增资料不自动触发模型调用。

## 验证

隔离数据库测试覆盖独立保存、场景改名、重复保存、归属校验、SQLite/D1 回滚、备份恢复和敏感过滤。
界面测试使用拦截 API 的虚拟档案，不写入真实资料，覆盖切换、保存失败重试、刷新、URL 场景筛选、离开保护和桌面/390px/320px。
